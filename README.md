# Codelint — AI Code Review Assistant

A full-stack tool that performs real static analysis on Python code — no fake
"AI says this looks fine" output. It parses your code into an Abstract Syntax
Tree (the same technique real linters like `pylint` and `bandit` use), scores
it, stores every run in a database, and visualizes trends on a dashboard.

## What it demonstrates

- **Algorithms & data structures**: AST traversal, cyclomatic complexity
  computation (the McCabe metric), weighted scoring.
- **Backend/API design**: REST API built with FastAPI (routes, request
  validation with Pydantic, error handling).
- **Databases**: SQLAlchemy ORM models, persisted analysis history in SQLite.
- **Applied static/security analysis**: detects real bug patterns (mutable
  default args, bare excepts, `==` vs `is`), security risks (`eval`/`exec`,
  `shell=True`, hardcoded secrets), and style issues.
- **Frontend**: a hand-built dashboard (vanilla HTML/CSS/JS + Chart.js) with
  three views — analyze, history, dashboard.

## Running it locally

### 1. Backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

The API is now live at `http://localhost:8000`. Interactive API docs
(auto-generated by FastAPI) are at `http://localhost:8000/docs`.

A `code_review.db` SQLite file is created automatically on first run —
no database setup needed.

### 2. Frontend

The frontend is plain HTML/CSS/JS, so no build step is required. Just serve
the folder:

```bash
cd frontend
python3 -m http.server 5500
```

Then open `http://localhost:5500` in your browser. (Opening `index.html`
directly with `file://` also works in most browsers, since it just calls
the API over `fetch`.)

## How the scoring works

Every analysis starts at 100 points. Each issue found deducts points based
on severity:

| Severity | Deduction | Examples |
|----------|-----------|----------|
| High     | 8 pts     | `eval()`/`exec()`, `shell=True`, hardcoded secrets, mutable default args, high complexity |
| Medium   | 4 pts     | bare `except:`, long functions, moderate complexity |
| Low      | 1.5 pts   | missing docstrings, long lines, `==` vs `is` |

## Extending it

Ideas if you want to keep building on this:
- Add a second language analyzer (e.g. a JS linter via regex/AST-equivalent)
- Swap the rule-based engine for an LLM call (Anthropic API) that explains
  *why* an issue matters, on top of the deterministic AST findings
- Add user accounts so history is per-user instead of global
- Deploy the backend (Render/Fly.io) and frontend (Vercel/Netlify) so it's a
  live link for your resume, not just a local demo
